|---|---|---|---|---|
| F-01 | Функциональное | Просмотр баланса своего счёта | Сравнить ответ с тестовыми данными | Факт |
| F-02 | Функциональное | Просмотр истории своего счёта | Сравнить ответ с тестовыми данными | Факт |
| F-03 | Функциональное | Создание заявки в поддержку | Создать заявку, получить ID, посмотреть заявку с таким ID и сравнить | Факт |
| F-04 | Функциональное | Абонент входит в кабинет по логину и паролю | Войти тестовым абонентом с верным и неверным паролем | Допущение |
| N-01 | Нефункциональное | Заявка доступна после пересоздания приложения | Создать, пересоздать, прочитать и сравнить | Согласовано |
| N-02 | Нефункциональное | Получение баланса через API: p95 <= 500 мс при 0,67 RPS | Нагрузочный тест | Допущение |
| N-03 | Нефункциональное | При потере узла с БД RTO < 30 мин, RPO < 1 ч | Зафиксировать время последней копии, отказа и проверенного восстановления, сравнить с порогами | Допущение |
| N-04 | Нефункциональное | Резервная копия хранится вне узла с БД и переживает его потерю | Удалить узел с БД, восстановиться из копии на новом узле | Допущение |
| N-05 | Нефункциональное | После перезагрузки ВМ сервис отвечает без ручных действий через ≤ 5 мин | Перезагрузить ВМ, засечь время до первого успешного ответа | Допущение |
| N-06 | Нефункциональное | Пароли абонентов хранятся в БД в виде хеша, а не открытым текстом | Посмотреть таблицу пользователей в БД | Допущение |
| N-06 | Нефункциональное | Приложение подключается к БД под отдельным пользователем с ограниченными правами | Попробовать удалить таблицу под пользователем приложения, ожидать отказ | Допущение |
| N-07 | Нефункциональное | БД недоступна снаружи, открыт только порт приложения | Подключиться к порту БД с внешней машины, ожидать отказ | Допущение |
| N-06 | Нефункциональное | Копии БД в хранилище вне ВМ с самой БД, ежедневная полная копия + архив журналов транзакций | Восстановить на чистую БД, сравнить число записей по таблицам | Допущение |
| O-01 | Ограничение | Условный бюджет 4 vCPU, 8 ГБ RAM, 60 ГБ | Сравнить потребление после теста | Допущение |

Исходное ожидание по сохранности данных: данные пользователей сохраняются при сбоях.
Согласованное ограничение учебного стенда: при потере узла с БД допускаемое RPO <= 1 ч и RTO <= 30 мин.
Сценарий отказа, для которого заданы RTO и RPO: потеря узла с базой данных.

## 5. Предварительная оценка ресурсов
 Модель нагрузки:
- Активные в пик: 1 000 × 2% = 20 пользователей.
- Поток запросов: 20 / 30 с ≈ 0,67 RPS.
Профиль операций: просмотр баланса 50%, истории 40%, создание заявки 10%.
 
Оценка полного объёма данных и роста при горизонте в 90 дней:
 
| Составляющая | Расчёт | Объём |
|---|---|---|
| Полезные данные | 1 000 × 150 × 1 КБ | 0,15 ГБ |
| С индексами | 0,15 × 1,5 | 0,225 ГБ |
| Рост за 90 дней | 1 000 × 15 записей × 1 КБ × 1,5 | 0,0225 ГБ |
| Логи за 7 дней | 0,5 × 7 | 3,5 ГБ |
| ОС и образы | Учебное допущение | 10 ГБ |
| Итого с запасом 30% | (0,225 + 0,0225 + 3,5 + 10) × 1,3 | ≈ 17,88 ГБ |
 

 
| Потребитель | RAM, ГБ |
|---|---|
| ОС и служебные процессы | 1 |
| Приложение | 1,5 |
| База данных | 3 |
| Кэш | 0,5 |
| Средства наблюдения | 1 |
| Запас | 1 |
| Итого | 8 |
 
Объём и размещение резервных копий учитываются отдельно: (0,225 + 0,0225) × 3 ≈ 0,74 ГБ, хранятся отдельно от сервера с БД.
 
Итого по CPU и RAM: 4 vCPU на все компоненты, RAM 7 ГБ + 1 ГБ запас.
 
Неучтённые накладные расходы: временные пики нагрузки, рост логов.
 
План проверки: 0,67 RPS, 2 минуты прогрева и 10 минут измерения; метрики p95, ошибки, CPU, RAM, диск; успех — p95 <= 500 мс, ошибок <= 1%.
